## 3. Ошибки ИИ и их исправление

1. **Типовые импорты при `verbatimModuleSyntax: true`**
   * **Проблема:** ИИ изначально сгенерировал импорты интерфейсов и типов стандартным образом: `import { Run } from '../types/run'`. В шаблоне Vite с включённой опцией `verbatimModuleSyntax: true` это привело к ошибке компиляции TypeScript: `'Run' is a type and must be imported using a type-only import`.
   * **Исправление:** Все импорты типов и интерфейсов во всём проекте переведены на явный синтаксис `import type { ... }`.

2. **Конфликт типов Vitest в `vite.config.ts`**
   * **Проблема:** При добавлении секции `test` в `vite.config.ts` вызвалась ошибка перегрузки типов: `Object literal may only specify known properties, and 'test' does not exist in type 'UserConfigExport'`.
   * **Исправление:** Конфигурация Vitest была вынесена в `vitest.config.ts` с явным импортом `defineConfig` из `'vitest/config'`, что изолировало типы тестов от основного сборщика Vite.

3. **Монолитный `App.tsx` и вынос `Header`**
   * **Проблема:** Первоначально ИИ разместил шапку приложения и логику тумблера симуляции ошибки прямо внутри `App.tsx`, что нарушало требование ТЗ по декомпозиции компонентов.
   * **Исправление:** Разметка и стили шапки вынесены в отдельный компонент `src/components/layout/Header.tsx`, оставив в `App.tsx` только координирующую бизнес-логику.
